01the turn

it didn't vanish. it moved up a level.

you stopped writing lines and started directing systems. the work is still hard. it's just hard somewhere else now: guiding agents, unblocking them, owning that the output is correct.

02the thesis
5 → 500

a team of 5 engineers with agents is a team of 500. everyone knows the output explodes. what nobody plans for: the structure does too. that's the whole talk.

02the thesis

you inherited a 500-person org's problems with a 5-person team.

coordination. review throughput. drift. institutional memory. none of these were engineering problems at 5 humans. all of them are now, overnight, with nobody new to delegate them to. if it feels like things are spinning out of control, this is why: a 500-person org run on 5-person habits is chaos by construction.

02the thesis

everything else here is downstream of one number.

areview doesn't scale← 500

03what breaks

you cannot review 500 engineers by hand.

5 humans reviewing the output of 495 agents isn't a process, it's a LARP. human-in-every-PR does not survive contact with the throughput.

03what breaks

claude.md is a suggestion.

a rule an agent can ignore is a vibe. if it must hold, it has to live somewhere the agent won't route around: linters, the type system, hooks, a reviewer that blocks the merge. "please don't" is not an architecture.

03what breaks

institutional memory evaporates by default.

the long-tenured engineer who "just knows why" doesn't exist on an agent fleet. so you manufacture the memory: topology maps, knowledge graphs, written context the agents actually load before they touch anything.

04the machinery

give me the loops, bröther.

every break has the same fix shape: a loop. something fires, an agent handles it, a gate checks it, repeat. you stop doing the task and start owning the loop that does the task.

04the machinery

anything you do twice is a loop you haven't built yet.

the skill isn't doing the work. it's seeing the loop and closing it. review, deps, issues, CI, releases. loop loop loop.

05supporting machinery

enforce with tools.

written rules drift. a linter doesn't. push every "agents should always X" down into something mechanical: lint rule, type, pre-commit, hook, blocking reviewer. if a human has to remember it, it's already broken.

05supporting machinery

treat agents like coworkers.

a good coworker has context and can unblock themselves. give the fleet the same: the docs, the topology, the ability to read logs, run tests, open issues. an agent that has to ask you everything is a junior you forgot to onboard.

05supporting machinery

pick languages your agents are good at.

rust, go, bun with strict typescript. offload correctness to the compiler instead of to human eyeballs. a strong toolchain catches the agent's mistakes before you have to.

06objections, in passing
"the spend, though?"
token cost on directed work is a rounding error next to salary. the only spend that hurts is waste from bad direction.
"what when claude is down?"
what do you do when aws or github is down? you live with the dependency, same as every other one.
"model agnostic?"
nice to have, don't lose sleep over it. are you cloud-provider agnostic? exactly.
"which harness?"
the differences collapsed. standardize on one for team coherence. it's not that deep, just pick one.
07what's still yours

"i don't debug" is bait.

1observe the bug, get a repro
2infer proximal cause via mental model
3hand agent failure + hypothesis
4interrogate the answer
5direct the fix

adversarial verification. the loop doesn't terminate until i can explain it myself.

07what's still yours

i don't ship what i can't explain.

same gate as debugging. a slick, Confident fix i can't reconstruct gets zero trust from me. the model's confidence is not evidence. my comprehension is the ship / no-ship bar.

07what's still yours

when a bug ships, fix the reviewer.

1notice the escape
2triage which reviewer missed it
3sharpen it, or add a specialist
4ship the policy change

escapes are feedback. the fleet can't see what it failed to catch, so noticing is yours. you manage the agents that write the code and the agents that review it.

07what's still yours

judgment is still king.

directing what gets built, deciding how, holding the mental model of the system. that's the job now. and if you notice you've lost the mental model: stop. make the model teach you the system before you ship another thing.

08parting thoughts

you are not pushing your models hard enough.

almost nobody is. and if pushing hard has only bought you mess so far, you weren't short on effort, you were short on structure. the gap between what these things can do and what teams get from them is the entire opportunity. close it.
